### 2.5 F9 — versioned HMAC, and three bugs in its own first draft

On `main`, national IDs were stored and matched as **plaintext 13 digits**; the normaliser returned **raw text**
for malformed input; `maskIdentifierForLog` was reachable only from dead code; and there was **no `createHmac`
anywhere** in the backend.

`nationalIdContract.js` implements HMAC-SHA-256 with a versioned secret. HMAC and never a bare SHA-256, because a
Thai national ID's body plus checksum is enumerable — a test asserts the stored value is **not** `sha256(id)`.
Writes use the highest version and record it; lookups try every accepted version, so rotation does not orphan
rows. With no key, operations return **503**; there is no plaintext and no unkeyed fallback.

Three defects were found **in the work itself**:

1. My raw-value normaliser blanked 64-hex digests, so every national-ID lookup would have missed and every
   re-link created a duplicate. Fixed with a documented `normalizeLookupValue`.
2. Cross-version duplicates were accepted — `UNIQUE(id_type,id_value)` compares digests, so a v1 row and a v2
   write let **two employees claim one national ID**. **Reproduced on real MariaDB (2 rows, 2 employees).** Fixed
   with a cross-version probe; now 409.
3. CI caught that I had named `lookup_key_version` in **every** identifier INSERT, breaking `personnel_id` /
   `facescan_id` writes on any schema without migration 029 (then 015). Narrowed to the national-ID path only; a pre-029
   write now fails with coded **503 `NATIONAL_ID_STORAGE_NOT_READY`**.

Proven on both schemas: **4/4** on main's, **13/13** on the 015 schema.

### 2.7 SSO local QA — the contract is not OAuth

The vendor sample shows the callback parameter is **`ac`** and the token exchange is `POST …/token.aspx` with
`{clientID, code}` — **no client secret, no `grant_type`, no `state`**. RAE V2 reads `code` and requires a secret,
but the portal path is hard-blocked with `SSO_NOT_READY`. **No protocol was changed on the strength of a sample
file**; the mismatch is documented for vendor confirmation.

Signout was implemented against the real architecture (bearer token in `localStorage`, **no auth cookie**) and
refuses three things from the sample: the `mju.ac.th` parent-domain cookie, the sample client ID, and an
expiry without `Path`/`Secure`/`HttpOnly`/`SameSite`.
