## 2. The two findings that justified the session

### 2.1 A security control that was asserted but did not work (ID-7b)

`enrichmentBlocksApproval` was a **blocklist**. An **absent** outcome meant "nothing to block" — and because
`enrichment_outcome` is **not a column** in any of the 24 migrations, that was the state of **every**
production row, while **every fixture test passed** (the fixture twin persists the field). So an enrichment
link with outcome `ambiguous`/`not_found`/`timeout`/`api_error`/`fallback`/`firstname_only` and `confidence`
`high`/`medium` was **approvable on MariaDB**.

**Fixed** by inverting to an **allowlist with an explicit absence check** (`ALLOWED_ENRICHMENT_OUTCOMES =
['found']`), which needed **no migration**. Verified **2/2 on a real MariaDB 11.4.2**. Known consequence,
stated not hidden: until the column exists, **no enrichment link can be approved on MariaDB at all** — the
intended posture.

### 2.2 A real national ID is in this public repository

A checksum-valid 13-digit value used as a "synthetic" test fixture is byte-identical to a real `citizenID`
cached by the MJU Person API (~1 in 10¹³ by chance). Verified: **6 files, 28 occurrences in 4 encodings**
(plain, dashed, Thai digits, full-width); present on **`origin/main`**; **not** one of RAE's 50 in-scope
employees (membership-only test; no CSV value read out).

Redacted in the working tree, a recurrence guard added, and the incident recorded as
[`SECURITY_INCIDENT_PII_IN_FIXTURES_20261016.md`](../SECURITY_INCIDENT_PII_IN_FIXTURES_20261016.md) — which
remains **OPEN** because **history remediation and notification are owner decisions**.
