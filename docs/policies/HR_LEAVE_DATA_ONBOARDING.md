# HR leave data onboarding — templates, validation and dry-run design

> สถานะ: เครื่องมือนำเข้า `leave:import-hr-data` พร้อมแล้ว (PR 2c) แต่ **ยังไม่ได้รันกับ production**; migration 034–036 ยังไม่ถูก apply บน production. ใช้คู่กับ
> `MJU_LEAVE_POLICY_2569.md` (กติกา) และ `LEAVE_ENGINE_PHASE2_PLAN.md` (การเชื่อมระบบ).
> เทมเพลตเป็นไฟล์ที่มีเฉพาะหัวคอลัมน์ ไม่มีข้อมูลตัวอย่าง: `docs/hr-templates/`.

## 1. ใครต้องกรอก

เฉพาะผู้ที่ engine ต้องคำนวณสิทธิ์ให้ ณ ข้อมูลวันที่ 2026-11-23 (52 คนที่ปฏิบัติงานอยู่):

| กลุ่ม | จำนวน | ต้องกรอก |
|---|---:|---|
| `university` (พนักงานมหาวิทยาลัย) | 28 | ใช่ |
| `department` (พนักงานส่วนงาน) | 4 | ใช่ + ยืนยันสิทธิ์ (ประกาศไม่ได้นิยามคำนี้) |
| `procurement_academic` (นักวิชาการพัสดุ) | 1 | ใช่ + ยืนยันสิทธิ์ |
| `contract` (ส่วนงานจ้างเหมา) | 19 | ไม่ต้อง (นอกขอบเขตประกาศ) |

รวมอย่างน้อย **33 คน**. ไม่ต้องส่งแถวของผู้ที่อยู่นอกขอบเขต; ถ้าส่งมา ระบบจะรายงานเป็นข้อผิดพลาดแบบบล็อก (ดู §4).

## 2. ไฟล์ที่ 1 — ข้อมูลบุคลากรด้านการลา (`hr_leave_profile_template.csv`)

หนึ่งแถวต่อหนึ่งคน (ข้อเท็จจริงที่แทบไม่เปลี่ยน).

| คอลัมน์ | ชื่อฟิลด์ | จำเป็น | ความหมาย / ค่าที่รับ |
|---|---|---|---|
| รหัส | `employee_id` | ใช่ | รหัสพนักงาน 4 หลัก ตรงกับ `employees.employee_id` ทุกตัวอักษร (ตั้งคอลัมน์เป็น "ข้อความ" ใน Excel) ใช้จับคู่เท่านั้น ไม่สร้างพนักงานใหม่ |
| ชื่อ-นามสกุล | — | ไม่ | ไว้ให้คนอ่านตรวจเทียบ **ไม่เก็บและไม่ใช้จับคู่**; ไม่ตรงกับทะเบียน = เตือน (นับจำนวน) |
| ประเภทบุคลากร | — | ไม่ | ไว้ตรวจเทียบกับ `employees.employee_type` (ค่าตามไฟล์บุคลากร: พนักงานมหาวิทยาลัย / พนักงานส่วนงาน / พนักงานส่วนงานจ้างเหมา / นักวิชาการพัสดุ) ไม่ตรง = ข้อผิดพลาดแบบบล็อก (แก้ที่ไฟล์บุคลากร ไม่ใช่ที่นี่) |
| วันที่เริ่มงาน | `hire_date` | ใช่ | วันที่ได้รับการบรรจุ/เริ่มสัญญาปัจจุบันเป็นพนักงานมหาวิทยาลัย → `employees.hire_date` (คอลัมน์มีอยู่แล้ว) |
| วันที่เริ่มปฏิบัติงานต่อเนื่อง | `continuous_service_start` | ใช่ถ้าทราบ | วันที่เริ่มปฏิบัติงานติดต่อกันโดยนับต่อเนื่องตามข้อ 62 (เปลี่ยนสถานภาพจากข้าราชการ/ลูกจ้างประจำ/พนักงานเงินรายได้, หรือจ้างต่อเนื่องหลังเกษียณ/สิ้นสุดสัญญา) ต้องไม่หลังวันที่เริ่มงาน; **เท่ากับวันที่เริ่มงานถ้าไม่มีช่วงก่อนหน้า**; เว้นว่าง = "ไม่ทราบ" (ไม่ใช่ "ไม่มี") |
| ประเภทการบรรจุ | `appointment_kind` | ใช่ถ้าเริ่มงานตั้งแต่ 2025-10-01 | `บรรจุครั้งแรก` · `กลับมาบรรจุใหม่หลังลาออกเพราะเหตุส่วนตัว` · `กลับมาบรรจุใหม่หลังถูกสั่งให้ออก` · `อื่น ๆ (เปลี่ยนสถานภาพ/จ้างต่อเนื่อง)` — ใช้ตัดสินข้อ 23 (ไม่มีสิทธิ์พักผ่อนในปีบรรจุที่ยังไม่ถึง 6 เดือน) |
| การยืนยันสิทธิ์ตามประกาศ | `eligibility_confirmed` | แนะนำสำหรับ `department` / `procurement_academic` | `ใช่` = อยู่ในขอบเขตประกาศ · `ไม่ใช่` = นอกขอบเขต · ว่าง = ยังไม่ยืนยัน (ระบบคง `needs_hr`) |
| เลขที่หนังสือยืนยัน | `eligibility_reference` | ใช่ถ้ากรอกคอลัมน์ก่อนหน้า | เลขที่หนังสือ/บันทึก HR ที่ยืนยัน |
| แหล่งข้อมูล/เอกสารอ้างอิง | `source_reference` | ใช่ทุกแถว | เอกสารที่มาของข้อมูลในแถวนี้ (เช่น ทะเบียนประวัติ, คำสั่งบรรจุ เลขที่…) |
| หมายเหตุ | `note` | ไม่ | ข้อความอิสระ ≤ 200 ตัวอักษร |

## 3. ไฟล์ที่ 2 — สิทธิ์ลาที่ HR รับรอง (`hr_leave_entitlement_template.csv`)

หนึ่งแถวต่อ (คน, ปีงบประมาณ, ประเภทการลา). จำเป็นอย่างน้อยสำหรับ **ลาพักผ่อน FY2570** เพราะยอดยกมาคำนวณเองไม่ได้.

| คอลัมน์ | ชื่อฟิลด์ | จำเป็น | ความหมาย / ค่าที่รับ |
|---|---|---|---|
| รหัส | `employee_id` | ใช่ | เหมือนไฟล์ที่ 1 |
| ปีงบประมาณ (พ.ศ.) | `fiscal_year_be` | ใช่ | ปี พ.ศ. ที่ปีงบประมาณสิ้นสุด: 2570 = 1 ต.ค. 2569 – 30 ก.ย. 2570 (CE 2026-10-01..2027-09-30). รับ 2569 ขึ้นไป |
| ประเภทการลา | `leave_type` | ใช่ | `ลาป่วย` · `ลากิจส่วนตัว` · `ลาพักผ่อน` |
| สิทธิ์ที่ได้รับในปีนี้ (วันทำการ) | `entitlement_days` | ใช่ | สิทธิ์ของปีนั้น **ไม่รวมยอดยกมา** (เช่น ลาพักผ่อน 10, ลากิจปีแรก 15) ขั้นละ 0.5; ช่วง 0–120 |
| ยอดสะสมยกมา (วันทำการ) | `carryover_days` | เฉพาะลาพักผ่อน | ยอดวันพักผ่อนที่ HR รับรองว่ายกมาจากปีงบประมาณก่อน (ข้อ 24) ขั้นละ 0.5; ช่วง 0–30; ประเภทอื่นต้องเว้นว่าง; `0` = HR ยืนยันว่าไม่มียอดยกมา, เว้นว่าง = ไม่ทราบ |
| ใช้ไปแล้วก่อนเริ่มนับในระบบ (วันทำการ) | `usage_baseline_days` | ไม่ | วันที่ใช้ไปแล้ว **ซึ่งไม่อยู่ในรายการลาของระบบ** (เช่น ก่อนเริ่มนำเข้า HIP) ถ้าไม่มี เว้นว่าง |
| นับถึงวันที่ | `usage_baseline_through` | ใช่ถ้ากรอกคอลัมน์ก่อนหน้า | วันสุดท้ายที่ยอดข้างต้นครอบคลุม; รายการลาของระบบที่ลงวันที่ **ไม่เกินวันนี้** จะไม่ถูกหักซ้ำ |
| แหล่งข้อมูล/เอกสารอ้างอิง | `source_reference` | ใช่ทุกแถว | เอกสารที่มา |
| หมายเหตุ | `note` | ไม่ | ≤ 200 ตัวอักษร |

**HR ส่ง "สิทธิ์" ไม่ใช่ "คงเหลือ".** ยอดคงเหลือคำนวณเสมอจากสิทธิ์ − วันลาที่อนุมัติแล้ว เพื่อไม่ให้หักซ้ำ (ดู Phase 2 plan §3).

## 4. กติกาตรวจสอบ (validation)

ผลทุกแถวเป็น **error** (บล็อก `--confirm`) หรือ **warning** (นับ รายงาน แต่ไม่บล็อก).

รูปแบบไฟล์ (error ทั้งไฟล์): UTF-8 (BOM ได้), ตัวคั่น `,`, ขึ้นบรรทัดใหม่ CRLF/LF, หัวคอลัมน์ตรงกับเทมเพลตทุกชื่อ (ลำดับสลับได้), ไม่มีคอลัมน์แปลกปลอม, ไม่เกิน 1,000 แถว.

| รหัส | ระดับ | เงื่อนไข |
|---|---|---|
| `id_format` | error | `รหัส` ไม่ใช่เลข 4 หลักพอดี (ปฏิเสธรูป `1234.0`, `1.2E3`, ช่องว่างนำ/ท้าย) |
| `id_duplicate` | error | ไฟล์ที่ 1: รหัสซ้ำ · ไฟล์ที่ 2: (รหัส, ปี, ประเภท) ซ้ำ |
| `id_not_found` | error | ไม่มีพนักงานรหัสนี้ในทะเบียน (ไม่สร้างใหม่) |
| `not_active` | error | พนักงานไม่ได้อยู่สถานะปฏิบัติงานอยู่ |
| `type_out_of_scope` | error | พนักงานเป็น `contract` และไม่มีการยืนยันสิทธิ์ `ใช่` พร้อมเลขที่หนังสือ |
| `type_mismatch` | error | ประเภทบุคลากรในไฟล์ไม่ตรงกับทะเบียน |
| `date_format` | error | วันที่ไม่ใช่ `YYYY-MM-DD` (ค.ศ.) หรือ `DD/MM/YYYY` ที่ปี ≥ 2400 (พ.ศ.) · วันที่ไม่มีจริง · ปี ค.ศ. นอก 1950–2100 |
| `hire_in_future` | error | วันที่เริ่มงาน > วันนี้ + 366 วัน |
| `continuity_after_hire` | error | วันที่เริ่มปฏิบัติงานต่อเนื่อง > วันที่เริ่มงาน |
| `appointment_kind_unknown` | error | ค่าไม่อยู่ในรายการ 4 ค่า |
| `appointment_kind_missing` | error | วันที่เริ่มงานตั้งแต่ 2025-10-01 แต่ไม่ระบุประเภทการบรรจุ |
| `confirmation_value` | error | การยืนยันสิทธิ์ไม่ใช่ `ใช่` / `ไม่ใช่` |
| `row_columns` | error | จำนวนคอลัมน์ในแถวไม่ตรงกับหัวตาราง |
| `note_too_long` | error | หมายเหตุเกิน 200 ตัวอักษร |
| `confirmation_needs_reference` | error | มี `การยืนยันสิทธิ์` แต่ไม่มี `เลขที่หนังสือยืนยัน` |
| `source_missing` | error | ไม่มี `แหล่งข้อมูล/เอกสารอ้างอิง` |
| `fiscal_year_range` | error | ปีงบประมาณ < 2569 หรือ > ปีงบประมาณปัจจุบัน + 1 |
| `leave_type_unknown` | error | ค่าไม่ใช่ 3 ประเภท |
| `days_format` | error | ไม่ใช่ตัวเลขทศนิยมขั้น 0.5 หรือนอกช่วงที่กำหนด |
| `carryover_not_vacation` | error | กรอกยอดยกมาในประเภทที่ไม่ใช่ลาพักผ่อน |
| `baseline_pair` | error | กรอกอย่างใดอย่างหนึ่งของ (ใช้ไปแล้ว, นับถึงวันที่) · หรือวันที่อยู่นอกปีงบประมาณนั้น |
| `hire_missing` | warning | แถวไฟล์ที่ 1 ไม่มีวันที่เริ่มงาน (engine จะยัง `unknown`) |
| `no_data` | warning | แถวไฟล์ที่ 1 ไม่มีข้อมูลใดให้บันทึก |
| `eligibility_unconfirmed` | warning | `department` / `procurement_academic` ที่ยังไม่มีการยืนยันสิทธิ์ (คง `needs_hr`) |
| `vacation_cap_exceeded` | warning | สิทธิ์ + ยอดยกมา เกินเพดาน 20 วัน (30 วันเมื่อเริ่มปฏิบัติงานต่อเนื่องครบ 10 ปี ณ ต้นปีงบประมาณ ถ้าทราบ) |
| `differs_from_policy` | warning | ตัวเลขของ HR ต่างจากที่ engine คำนวณได้ (HR ชนะ แต่แสดงเป็นธง) |
| `name_mismatch` | warning | ชื่อในไฟล์ต่างจากทะเบียน |
| `conflicts_with_existing` | warning | ค่าต่างจากที่บันทึกไว้แล้ว (จะเขียนทับพร้อมบันทึก audit) |

เซลล์ว่าง **ไม่เขียนทับ** ค่าที่มีอยู่ ถ้าต้องการล้างค่าให้ใส่ `-` (ต้องมีแหล่งอ้างอิง).

## 5. กระบวนการนำเข้าแบบ dry-run (ใช้งานได้ — `npm run leave:import-hr-data`)

ไฟล์ระดับตาราง (`missing_column`, `unknown_column`, `duplicate_column`, `too_many_rows`, `empty_file`, `unterminated_quote`) ถูกปฏิเสธก่อนอ่านแถวใด ๆ; dry-run ที่พบ error คืน exit code 3. `--report <ไฟล์>` เขียน `kind,line,level,code` ต่อรายการ (เลขแถว + รหัส ไม่มีค่าส่วนบุคคล). ใช้แบบแผนเดียวกับ `employees:import-profile`: จับคู่ด้วย `employee_id` เท่านั้น, dry-run เป็นค่าเริ่มต้น, ผลลัพธ์เป็นตัวเลขอย่างเดียว (ไม่พิมพ์รหัส/ชื่อ), `--confirm --operator <employee_uid>` ต้องมีสิทธิ์ข้อมูลระดับกว้างและ `DATA_SOURCE=mariadb`.

```
leave:import-hr-data --profile <csv> [--entitlement <csv>]                      # dry-run
leave:import-hr-data --profile <csv> [--entitlement <csv>] --confirm --operator <uid>
```

1. **Parse + ตรวจรูปแบบไฟล์** (§4) ล้มเหลว = หยุดทันที ไม่มีผลข้างเคียง.
2. **ตรวจรายแถว** → นับ error/warning ตามรหัส. รายงานรายแถว (เลขแถว + รหัสข้อผิดพลาดเท่านั้น ไม่มีค่าส่วนบุคคล) เขียนลงไฟล์ท้องถิ่นของผู้รัน.
3. **จับคู่** กับ `employees` (อ่านอย่างเดียว) และเทียบกับค่าปัจจุบัน → นับ `ใหม่ / ไม่เปลี่ยน / จะเปลี่ยน`.
4. **Preview ด้วย engine** (หน่วยความจำ ไม่เขียน): รัน `computeEntitlements` กับข้อมูลหลังนำเข้าสมมติ → รายงานจำนวนคนต่อสถานะ (`ok / unknown / pending_hr_decision / needs_hr / pending_policy`) ก่อนและหลัง เพื่อให้เห็นว่าไฟล์ช่วยปิดช่องว่างได้เท่าใด.
5. **Dry-run จบที่นี่** (`written: false`).
6. **`--confirm`**: ปฏิเสธถ้ามี error ใด ๆ; ต้องสำรองฐานข้อมูลก่อน (ตาม runbook); เขียนในทรานแซกชันเดียว: `employees.hire_date`, ตารางโปรไฟล์ลา, ตารางสิทธิ์; บันทึกแบตช์ (SHA-256 ของไฟล์, จำนวนแถว, ผู้รัน, เวลา) และ audit ต่อฟิลด์ที่เปลี่ยน (ก่อน/หลัง ≤ 200 ตัวอักษรตามแบบ `employee_leave_record_audit`); ไฟล์เดิมที่นำเข้าซ้ำ (SHA เดิม) = ไม่ทำอะไร.
7. ไม่แตะ `leave_balance`, `employee_leave_record`, การอนุมัติ, สิทธิ์ผู้ใช้, อีเมล หรือ credential.

## 6. สิ่งที่ยังต้องรอ

การรันกับ production ต้องรอการอนุมัติ migration 034–036 (ดู `LEAVE_ENGINE_PHASE2_PLAN.md` §5), การสำรองฐานข้อมูล และไฟล์จาก HR. ระหว่างนี้ HR เตรียมไฟล์ตามเทมเพลตได้ทันที และตรวจรูปแบบไฟล์ได้ด้วย dry-run บนฐานข้อมูลชั่วคราว.
